# Flavor Code 1.3 可靠性契约

1.3.0 把“可以继续运行”升级为可验证的恢复、安全与验收契约。以下约束属于发布门禁，不是尽力而为的实现细节。

## Durable Harness

- 每个会话在 `.flavor/sessions/<session-id>.events.jsonl` 维护顺序递增、SHA-256 哈希链保护的事件日志。
- steer/follow-up 队列只有在 `fsync` 完成后才对调用方报告已接收；重启后恢复未确认项目，并用 claim/ack 避免重复消费。
- turn、模型请求、工具调用都记录开始与终态。日志保存可重放的完整提示、模型消息、不可变配置快照及输入哈希。
- 崩溃只允许留下一个未完成的 JSONL 尾部，恢复时截断该尾部；已提交记录被篡改或机械不变量失败时拒绝启动。
- 只读工具默认标记为 `retrySafe`。未完成的非幂等工具只报告 interrupted，绝不自动重放。
- 会话恢复、清理和保留策略同时覆盖事件日志，避免事件文件被误识别为普通会话。

事件日志包含完整模型输入和工具参数，用于本地审计与确定性恢复，因此必须像普通会话记录一样视为敏感本地数据，不应提交到版本库。

## Context Epoch 与 Prompt Cache

每个上下文 epoch 都保存一个版本化 UUID、开始时间、稳定系统消息、动态源状态和稳定源哈希。

稳定区包括核心 system prompt、`FLAVOR.md`、工作区指令和用户记忆。它在 epoch 内只构建一次；运行日期、模型状态、长期记忆、任务状态和本轮 Hook/Skill 上下文位于最后一个 cache breakpoint 之后。动态源变化以新的、有时间顺序的 system message 加入，绝不回写稳定前缀，因此相同 epoch 的缓存前缀逐字节一致。

动态源刷新采用 stale-while-revalidate：临时读取失败沿用上一次成功值。上下文压缩会显式开始新 epoch；session restore 与 fork 则恢复/克隆原始稳定消息，不重新渲染旧前缀。本轮临时上下文在模型调用后从活动窗口移除，但进入持久 visibility log，保证“模型看到的内容”可审计。

## 分层权限策略

策略按以下位置加载：

1. 托管策略：环境变量 `FLAVOR_MANAGED_PERMISSIONS` 指定的文件；
2. 用户策略：`~/.flavor-code/permissions.json`；
3. 项目策略：`.flavor/permissions.json`；
4. 本机项目覆盖：`.flavor/permissions.local.json`；
5. 运行时 session rules。

所有匹配规则取最严格结果：`deny > ask > allow`。内置硬拒绝不可被任何层级放宽。重复 ID、未知字段和失败的规则自测会阻止策略加载；被更严格规则遮蔽的规则会产生诊断。

```json
{
  "version": 1,
  "rules": [
    {
      "id": "verify-tests",
      "decision": "allow",
      "prefix": ["npm", "test"],
      "agent": "main",
      "match": [["npm", "test", "--", "--run"]],
      "notMatch": [["npm", "run", "release"]]
    },
    {
      "id": "deny-force-push",
      "decision": "deny",
      "prefix": ["git", "push", "--force"],
      "justification": "Force push requires an explicit workflow"
    }
  ]
}
```

`prefix`、`match` 与 `notMatch` 都是命令 token 数组，不是易产生边界歧义的字符串前缀；Windows 上按大小写不敏感匹配。

## 插件隔离与信任

产品运行时默认启用 Worker + VM 沙箱。插件只能加载其根目录内的相对模块，并通过受控 RPC 注册贡献；manifest 必须声明文件读写、网络、进程或 `runtime:in-process` 能力。加载元数据带有 manifest 与入口内容的 SHA-256 指纹，供宿主做内容级信任判断。

`pluginSandbox: false` 仅保留给明确受信任的旧插件兼容场景。进程内宿主可同时启用 `requireInProcessTrust`，此时插件必须声明 `runtime:in-process`，且其指纹必须通过 `authorizePlugin`；名称相同但内容变化的插件不能沿用旧信任。

## Goal Verification

- goal 创建时对 objective 与 plan 生成不可变 contract hash。
- 每轮验收持久化 Git 状态、workspace diff hash、宿主测试命令结果和 skeptic 判定，形成 evidence rounds。
- 代码发生变化但没有可运行的宿主验证命令时，状态为 blocked；验证失败时不能完成 goal。
- skeptic 输出无效、分类器不可用或证据不足时 fail closed，不再把基础设施错误误判成 achieved。

## 会话迁移与发布门禁

Session schema 升级至 v4，保存 Context Epoch 与 visibility log。v1/v2/v3 首次迁移前会以独占方式写入 `.vN.bak` 原始备份，再保存 v4 数据。

CI 在 Windows、macOS 和 Ubuntu 上覆盖 Node.js 20/24，并将 durable journal、Context Epoch、session migration、权限策略和 goal verification 组成独立的 `npm run test:reliability` 门禁。正式发布还需通过全量测试、TypeScript 检查、CLI/桌面构建、VS Code 类型检查和安装烟测。
